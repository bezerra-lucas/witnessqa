# WitnessQA 0.3.0 — native CI seam

This minor release adds the versioned `witnessqa-ci/v1` public interface without
changing the existing interactive commands.

The minimum Node.js runtime is now 20, matching the Playwright version resolved
by the immutable package lock.

## Added

- `witnessqa --version-json` reports version `0.3.0`, interface version and the
  clean immutable checkout HEAD plus the SHA-256 of `package-lock.json`.
- `witnessqa ci --job <json> --out <new-dir>` executes frozen agent journeys in
  the real Playwright worker and emits `witnessqa-ci-result/v1`.
- CI evidence is regenerated through the privacy-versioned allowlist and bound
  to job, harness, subject, DoD, plan, scenario and artifact hashes.

## Fail-closed behavior

- Functional failures preserve evidence and exit `1`; only fully passing real
  journeys exit `0`.
- Missing, empty, unknown, unsafe, incomplete, smoke-only or drifted execution
  exits `2`.
- The CI command refuses reused output directories and candidate-controlled
  request, input, scenario or output paths.
- A copied install executable must equal the tracked `cli.mjs`, and the complete
  harness checkout must remain clean before and after execution. CI results bind
  both the harness HEAD and package-lock digest.
- Output creation rejects symlink traversal and rechecks the parent identity and
  created real path before writing any evidence.
- Plans reject empty descriptions and scenarios reject ambiguous multi-action
  steps or URL assertions that only restate navigation.

Collection remains separate from approval. A downstream agent must inspect the
frozen observations and a deterministic controller must enforce the final gate.
