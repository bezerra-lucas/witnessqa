# WitnessQA 0.2.0 — evidence privacy hardening

Release candidate verified on 2026-09-04.

## Why this release exists

WitnessQA captures application state, so its outputs can contain credentials,
session material or customer data if evidence is treated as ordinary test
output. This release makes sanitized evidence an explicit boundary across local
runs, reports, comparisons, notifications, BYOK diagnostics and CI artifacts.

Previously tracked Domod scenario credentials were revoked and replaced with
environment references. Their values are intentionally absent from this
document and from the current tree.

## Security behavior

- Scenario `fill.value` fields are redacted recursively before persistence.
- HTML removes scripts, form values, iframe contents, configured private regions
  and common credential/PII patterns.
- Screenshots mask form controls, iframes, known fill values, stable application
  markers and scenario-specific selectors; a failed mask/capture emits no file.
- JSON, Markdown, URLs, notifications and provider responses are sanitized at
  their sinks.
- BYOK excludes HTML by default; explicit HTML opt-in still sends only a
  sanitized, truncated excerpt over HTTPS (localhost excepted for testing).
- Legacy evidence is reexecuted or excluded instead of being republished.
- Packer, exporter, visual diff and report server reject traversal and symlink
  sources. Visual diffs persist changed-pixel masks rather than source pixels.
- The composite GitHub Action uses a fresh temporary run, exports an allowlisted
  bundle and exposes correctly mapped `verdict`, `report-path` and
  `artifact-path` outputs. Its metadata now lives at the repository root, so the
  documented `owner/repository@ref` invocation is directly executable.
- The release gate approves only `pass` (exit `0`). Both `fail` (exit `1`) and
  `blocked` (exit `2`) reject the job while `always()` preserves evidence upload
  and PR reporting. Discovery capture errors, warnings, unknown verdicts and
  empty runs fail closed; unknown resumed verdicts are discarded and reexecuted.
- A run that stops before producing a flow still uploads a sanitized synthetic
  non-pass dossier, rather than losing the artifact or turning the gate green.
- Browser session state is kept outside run artifacts with owner-only POSIX
  permissions; Windows users must apply equivalent private ACLs.

## Verification record

- Automated suite: 54/54 passing, including a deliberately failing product
  scenario that proves the dossier records failures without failing the harness.
- Dependency audit: zero reported production vulnerabilities.
- Package dry run: includes the privacy guard, safe-path helper, exporter and
  security policy.
- Credential regression scan: zero occurrences of the two revoked scenario
  values in current tracked files.
- Manual fixture QA: three flows passed, producing 13 screenshots and a PASS
  dossier inspected in the collaborative browser.
- The CI Action-contract matrix invokes the root composite Action itself for
  PASS, FAIL and BLOCKED and checks its conclusion, verdict output and artifact
  path. Local CLI integration additionally verifies FAIL propagation, BLOCKED
  discovery and preserved dossiers.
- Independent Sol security review: no blocker, high or medium finding remained
  after the final recheck.

Synthetic public evidence lives in
[`marketing/landing/demo`](../../marketing/landing/demo). The privacy screenshot
shows separate black masks for a custom selector, a filled control and an
iframe. No remote customer or protected fixture data is used by that demo.

## Migration and residual risk

Consumers must move secrets into their CI secret store or ephemeral environment
and regenerate public artifacts. Existing raw runs and browser auth state should
be treated as sensitive and deleted according to the owner's retention policy.

Revoked historical values remain discoverable in published Git history, forks
or caches until a coordinated history rewrite occurs. Rewriting shared history
is deliberately outside this release because it is disruptive and requires an
explicit owner decision; revocation is the effective security boundary.

No generic detector can identify every sensitive name, address or pixel. Teams
must inspect a dossier before publication and configure stable
`data-witness-redact` markers or scenario `redaction.selectors` for their app.
