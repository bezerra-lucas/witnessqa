§ Procedure

It uses your app the way your users do — and writes it all down.

No specs to write, no selectors to maintain. Point WitnessQA at your app, give it test credentials, and it maps and exercises every flow — then explores branch paths a scripted test would never think to try.

STEP 01

Discovery

An agent opens your app cold and maps every screen, form, and flow it can reach — the way a new user would.

STEP 02

Branch exploration

Each decision point spawns a new agent path — a breadth-first search across your app's real state space, not a happy-path script.

STEP 03

Evidence collection

Screenshots at every step, console and network logs, reproduction sequences. Everything a developer needs, nothing they have to chase.

STEP 04

Verdict & investigation

A signed report with pass/fail per flow. On failure, the agent keeps digging until it can name the likely cause.

§ Questions, answered under oath

Frequently examined questions

Is this another E2E testing tool?
No. Traditional E2E tools execute scripts someone wrote and maintain. WitnessQA agents explore your live application, decide what to exercise, and produce evidence and verdicts. There are no specs to author and no selectors to repair.
Is it deterministic enough to gate deploys?
Each run is recorded end-to-end — screenshots, logs, and the exact sequence of actions — so any verdict is auditable and reproducible. Teams typically run WitnessQA on staging before release and treat the report as the release record.
Is my application data safe?
You provide dedicated test credentials and a staging or production-read-only environment. Evidence is stored encrypted, never used for training, and deleted on request. SOC 2 is on the roadmap.
What happens when the agent finds a bug?
It doesn't stop at a red X. The agent reproduces the failure, captures the network and console state at the moment of breakage, and writes a short investigation: what happened, where, and the likely cause — attached to the flow's section of the report.
Which apps are supported?
Web applications in any framework — if a browser can open it, a witness can test it. Native mobile is on the roadmap.
Why "witness"?
Because the agent doesn't have opinions about your code. It was there. It saw what happened, and it writes it down — with evidence.
